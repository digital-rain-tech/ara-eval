## High

### 1. Python and web evaluation paths have divergent OpenRouter contracts
File: `ara_eval/core.py`, `web/src/lib/openrouter.ts`, `web/src/app/api/evaluate/route.ts`
Line: n/a
Severity: high
Category: Holistic
Description: The Python and web evaluation paths duplicate core OpenRouter behavior but do not share the same runtime contract. The Python path uses larger completion limits, retry/backoff/pacing, raw response logging, provider metadata, and request DB tracing. The web path uses a smaller `max_tokens` value, no retry/backoff, partial logging, and no raw response/provider metadata. This can make web results less reliable and harder to compare against lab results.
Suggested fix: Extract and document a shared evaluation contract, then align both runtimes against it. If the differences are intentional, document them explicitly and add cross-runtime tests for request shape, parsing, gating, and persistence.

## Medium

### 2. Retry mode does not preserve alternate scenario files
File: `labs/lab-01-risk-fingerprinting.py`
Line: 96
Severity: medium
Category: Diff
Description: `--retry` inherits jurisdiction, rubric, structured mode, and all/core selection from the prior run, but it does not inherit the new `--scenarios-file` value because `_run` never records it. Retrying a failed Singapore or RWA run without manually passing the same scenario file will load `starter-scenarios.json`, produce mismatched scenario IDs, and can overwrite the retry target with the wrong scenario set.
Suggested fix: Persist `scenarios_file` in both DB metadata and output `_run`, inherit it in retry mode before calling `load_scenarios()`, and add a regression test covering retry metadata for alternate scenario files.

### 3. `ara_eval/core.py` is carrying too many unrelated responsibilities
File: `ara_eval/core.py`
Line: n/a
Severity: medium
Category: Holistic
Description: `core.py` is described as the single source of truth, but it combines environment loading, prompt rendering, provider integration, SQLite schema, JSON repair, gating, printing/report helpers, scenario loading, and retry policy. This raises the risk of agent or developer edits causing unrelated regressions.
Suggested fix: Split the module into focused components such as `config.py`, `prompts.py`, `providers/openrouter.py`, `persistence.py`, `gating.py`, and `scenarios.py`, while keeping `core.py` as a compatibility facade if needed.

### 4. Web package manager and lint workflows are inconsistent

Line: n/a
Severity: medium
Category: Holistic
Description: The web project has both npm and pnpm lockfiles, while CI and Docker use npm. The `npm run lint` script invokes `next lint`, but CI uses `npx eslint src/`, creating a stale or inconsistent local-vs-CI lint path.

### 5. Deployed environment validation is incomplete

Line: n/a
Severity: medium
Category: Holistic
